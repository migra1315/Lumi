# 任务执行状态反馈实现方案

## 1. 背景与目标

### 1.1 当前系统架构

**gRPC双向流通信机制**:
- `serverCommand` RPC: `stream ClientStreamMessage ↔ stream ServerStreamMessage`
  - 服务器通过 `ServerStreamMessage` 下发命令给机器人
  - 机器人通过 `ClientStreamMessage` 响应命令执行状态

- `clientUpload` RPC: `stream RobotUploadRequest ↔ stream RobotUploadResponse`
  - 机器人通过 `RobotUploadRequest` 上传状态数据（机器人状态、环境数据、设备数据）
  - 服务器通过 `RobotUploadResponse` 确认接收

**当前支持的命令类型**:
1. `TASK_CMD` - 任务下发（多站点巡检任务）
2. `ROBOT_MODE_CMD` - 机器人模式切换
3. `JOY_CONTROL_CMD` - 摇杆控制
4. `SET_MARKER_CMD` - 设置标记点
5. `CHARGE_CMD` - 充电控制
6. `POSITION_ADJUST_CMD` - 位置调整
7. `RESPONSE_CMD` - 响应确认

**命令执行流程**:
```
服务器 --[ServerStreamMessage]--> RobotControlSystem._handle_serverCommand()
    --> TaskManager.receive_command()
    --> TaskScheduler.add_command() [优先级队列]
    --> TaskScheduler._execute_command() [根据cmd_type路由]
    --> 具体执行器(_execute_task_command, _execute_mode_command等)
    --> RobotController.[操作方法]
```

**当前操作类型**:
- `OPEN_DOOR` - 开门操作
- `CLOSE_DOOR` - 关门操作
- `CAPTURE` - 拍照采集
- `SERVE` - 服务操作
- `NONE` - 无操作

### 1.2 实现目标

1. **在RobotController中实现操作逻辑**:
   - `capture(device_id)` - 拍照并返回base64图像数据
   - `open_door(door_ip)` - 开门操作，返回成功/失败
   - `close_door(door_ip)` - 关门操作，返回成功/失败
   - `serve(device_id)` - 服务操作，返回成功/失败

2. **通过serverCommand流反馈执行状态**:
   - 命令级别：命令接收确认、执行中、完成、失败
   - 任务级别：任务开始、站点进度、任务完成
   - 操作级别：操作开始、操作结果（成功/失败、图像数据）

3. **扩展proto定义**:
   - 扩展 `ClientStreamMessage` 支持更多反馈类型
   - 新增命令执行状态反馈消息
   - 新增操作结果反馈消息

**说明**:

- `OPERATION_RESULT` - 用于反馈具体操作的执行结果

```python
def _execute_operation(self, operation_config: OperationConfig) -> Dict[str, Any]:
    """执行特定操作（修改返回值为详细结果）"""
    operation_mode = operation_config.operation_mode

    if operation_mode == OperationMode.OPEN_DOOR:
        result = self._open_door(operation_config.door_ip)
    elif operation_mode == OperationMode.CLOSE_DOOR:
        result = self._close_door(operation_config.door_ip)
    elif operation_mode == OperationMode.CAPTURE:
        result = self._capture(operation_config.device_id)
    elif operation_mode == OperationMode.SERVE:
        result = self._serve(operation_config.device_id)
    else:
        self.logger.warning(f"未知操作模式: {operation_mode}")
        result = {
            'success': True,
            'message': f'跳过未知操作: {operation_mode}',
            'timestamp': time.time()
        }

    # 触发操作结果回调，传递给TaskManager
    if hasattr(self, '_trigger_operation_result_callback'):
        self._trigger_operation_result_callback(operation_config, result)

    return result
```

```python
def _trigger_operation_result_callback(self, operation_config: OperationConfig, result: Dict[str, Any]):
    """触发操作结果回调

    Args:
        operation_config: 操作配置
        result: 操作执行结果
    """
    # 构造操作结果数据
    operation_data = {
        'task_id': self.current_task.task_id if self.current_task else '',
        'station_id': self.current_station.station_config.station_id if self.current_station else '',
        'operation_mode': operation_config.operation_mode,
        'result': result
    }

    # 触发回调（传递给TaskManager）
    self._trigger_callback("on_operation_complete", operation_data)
```

```python
def _handle_command_status_callback(self, **kwargs):
    """处理命令状态变化回调

    Args:

    command = kwargs.get("command")
```

```python
        # 创建CommandStatusUpdate消息
        status_update = robot_pb2.CommandStatusUpdate(
            command_id=int(command.command_id) if command.command_id.isdigit() else hash(command.command_id),
            command_type=cmd_type_map.get(command.cmd_type, robot_pb2.CmdType.RESPONSE_CMD),
            status=status_map.get(command.status.value, robot_pb2.CommandStatus.COMMAND_STATUS_PENDING),
            message=command.error_message or f"命令状态: {command.status.value}",
            timestamp=int(time.time() * 1000),
            retry_count=command.retry_count
        )

        # 创建ClientStreamMessage
        client_msg = robot_pb2.ClientStreamMessage(
            command_id=int(command.command_id) if command.command_id.isdigit() else hash(command.command_id),
            command_time=int(time.time() * 1000),
            command_type=robot_pb2.ClientMessageType.COMMAND_STATUS_UPDATE,
            robot_id=self.robot_id,
            command_status=status_update
        )

        # 通过serverCommand流发送
        if self.server_command_manager and self.server_command_manager.is_stream_active:
            self.server_command_manager.send_message(client_msg)
            self.logger.info(f"命令状态更新已发送: {command.command_id} -> {command.status.value}")
        else:
            self.logger.warning("serverCommand流未激活，无法发送命令状态更新")

    except Exception as e:
        self.logger.error(f"发送命令状态更新异常: {e}")
```

```python
def _send_task_progress_update(self, task):
```

## 9. 注意事项

### 9.1 兼容性
- 保持向后兼容：旧版本不发送新消息类型
- Proto扩展使用新的字段编号（避免冲突）
- 服务器端需要同步更新以处理新的消息类型

### 9.2 性能
- 避免过于频繁发送状态更新（可配置发送间隔）
- 图像数据base64编码会增大传输量，考虑压缩或分块传输
- 使用异步发送，避免阻塞任务执行

### 9.3 错误处理
- 操作失败时记录详细错误信息
- 消息发送失败时本地记录（可选：持久化到数据库）
- 超时处理：操作超时视为失败

### 9.4 安全性
- 开门操作需要权限验证（可在服务器端验证）
- 敏感数据（如图像）可选加密传输
- 防止重放攻击（使用timestamp和唯一ID）

```python
def _execute_operation_with_retry(
    self,
    operation_config: OperationConfig,
    max_retries: int = 3
) -> Dict[str, Any]:
    """带重试的操作执行"""
    for attempt in range(max_retries + 1):
        result = self._execute_operation(operation_config)
        if result.get('success'):
            return result
        if attempt < max_retries:
```

### 10.3 批量图像采集

```python
def capture_batch(
    self,
    device_id: str,
    count: int = 1,
    interval: float = 0.5
) -> Dict[str, Any]:
    """批量拍照

    Args:
        device_id: 设备ID
        count: 拍照数量
        interval: 拍照间隔（秒）
    """
    images = []
    for i in range(count):
        result = self.capture(device_id)
        if result.get('success'):
            images.extend(result.get('images', []))
        if i < count - 1:
            time.sleep(interval)

    return {
        'success': len(images) > 0,
        'images': images,
        'message': f'采集了{len(images)}张图片',
        'device_id': device_id,
        'timestamp': time.time()
    }
```

```python
class MessageBuffer:
    """消息缓冲队列"""
    def __init__(self, max_size=100, flush_interval=1.0):
        self.buffer = []
        self.max_size = max_size
        self.flush_interval = flush_interval

    def add(self, message):
        """添加消息到缓冲区"""
        self.buffer.append(message)
        if len(self.buffer) >= self.max_size:
            self.flush()

    def flush(self):
        """批量发送缓冲区消息"""
        # 发送逻辑
        self.buffer.clear()
```

## 11. 总结

本方案实现了完整的任务执行状态反馈机制：

**核心功能**:
1. ✅ 命令级别状态反馈（接收、执行中、完成、失败）
2. ✅ 任务级别进度反馈（站点进度、完成情况）
3. ✅ 操作级别结果反馈（开门/关门/拍照/服务的执行结果）

**技术实现**:
1. ✅ Proto定义扩展（新增3种消息类型）
2. ✅ RobotController操作实现（4种操作方法）
3. ✅ TaskScheduler结果收集（操作结果回调）
4. ✅ TaskManager状态管理（命令状态追踪）
5. ✅ RobotControlSystem消息发送（通过serverCommand流）

**通信流程**:
```
服务器 --[ServerStreamMessage]--> 机器人（接收命令）
机器人 --[ClientStreamMessage:COMMAND_RESPONSE]--> 服务器（确认接收）
机器人 --[ClientStreamMessage:COMMAND_STATUS_UPDATE]--> 服务器（状态更新）
机器人 --[ClientStreamMessage:TASK_PROGRESS_UPDATE]--> 服务器（任务进度）
机器人 --[ClientStreamMessage:OPERATION_RESULT]--> 服务器（操作结果）
```

通过这套完整的反馈机制，服务器可以实时了解机器人的任务执行情况，包括：
- 任务是否被接收
- 任务执行到哪个站点
- 每个操作的执行结果（成功/失败、耗时、错误信息）
- 拍照操作的图像数据
