# 生产环境稳定性改进方案总结

> **项目目标**: 将Lumi机器人控制系统升级为适合无人值守运维的生产级系统
>
> **生成时间**: 2026-01-29
>
> **核心需求**: 高稳定性、细粒度远程控制、自动恢复能力

---

## 一、现状分析

### 1.1 当前架构存在的主要问题

#### 问题1: gRPC通信缺乏弹性
**现状描述**:
- `StreamManager` 在流断开后不会自动重连
- `RobotControlSystem._init_grpc_client()` 仅在启动时连接一次
- 流中断后整个系统失去与服务端的通信能力

**影响**:
- 网络抖动或服务端重启会导致机器人失联
- 需要手动重启机器人程序才能恢复通信
- 无法满足无人值守运维要求

**证据**:
```python
# StreamManager.py:151-162
except grpc.RpcError as e:
    if e.code() == grpc.StatusCode.CANCELLED:
        self.logger.info("RPC调用被取消")
    else:
        self.logger.error(f"RPC错误: {e}")
        self.stats['errors'] += 1
# 流中断后仅记录错误，没有重连逻辑
```

---

#### 问题2: 启动流程高度耦合
**现状描述**:
- `RobotControlSystem.start()` 方法中同时执行：
  1. 初始化TaskManager
  2. 初始化gRPC客户端
  3. TaskManager初始化时立即启动robot_controller硬件系统
- 三个层次的启动逻辑混杂在一起，无法独立控制

**影响**:
- 无法在建立通信后再启动硬件（需要先连接服务端，等待服务端指令）
- 硬件初始化失败会导致整个系统无法启动
- 无法实现分阶段启动和故障隔离

**证据**:
```python
# RobotControlSystem.py:157-186
def start(self):
    # 直接初始化TaskManager（内部会立即启动硬件）
    self.task_manager = TaskManager(self.config, use_mock=self.use_mock)
    # 初始化gRPC
    if not self._init_grpc_client():
        self.logger.error("gRPC客户端初始化失败")
        return
```

```python
# TaskManager.py:59-73
def _init_robot_controller(self):
    # 创建控制器
    self.robot_controller = MockRobotController(...)
    # 立即初始化硬件系统
    if not self.robot_controller.setup_system():
        raise Exception("机器人系统初始化失败")
```

---

#### 问题3: 缺少硬件分组控制
**现状描述**:
- 当前proto定义的命令类型中没有独立控制硬件子系统的命令
- `setup_system()` 一次性启动所有硬件（AGV、ARM、EXT）
- 无法单独启动、关闭、使能某个子系统

**影响**:
- 服务端无法细粒度控制机器人硬件状态
- 某个子系统故障会影响整体
- 无法实现分组运维（例如仅使用机械臂做检测，AGV保持待机）

**证据**:
```protobuf
// RobotService.proto:62-72
enum CmdType {
    RESPONSE_CMD = 0;
    ROBOT_MODE_CMD = 1;
    TASK_CMD = 2;
    JOY_CONTROL_CMD = 3;
    SET_MARKER_CMD = 4;
    CHARGE_CMD = 5;
    POSITION_ADJUST_CMD = 6;
    HEARTBEAT_CMD = 7;
    // 缺少: HARDWARE_CONTROL_CMD
}
```

---

#### 问题4: 缺少关节级手动控制
**现状描述**:
- 仅有 `JOY_CONTROL_CMD` 用于AGV手动控制（线速度、角速度）
- 没有机械臂6个关节和外部轴4个关节的独立控制命令
- 无法实现精细的远程手动操作

**影响**:
- 服务端无法远程调试和校准机械臂
- 无法远程处理复杂场景（如手动避障、微调位置）
- 维护人员需要现场操作

**证据**:
```protobuf
// RobotService.proto:289-293
message JoyControlCmd {
    string angular_velocity = 1; // 仅支持AGV角速度
    string linear_velocity = 2;  // 仅支持AGV线速度
}
// 缺少: ArmJointControl, ExtAxisControl
```

---

#### 问题5: 状态持久化不完整
**现状描述**:
- 数据库保存任务执行状态，但不保存硬件系统状态
- 程序重启后无法恢复：
  - 哪些硬件子系统已启动
  - 硬件当前的使能状态
  - 断线期间执行的任务状态
- 用户要求重启后清空任务，但没有清理机制

**影响**:
- 重启后系统状态不一致
- 断线期间执行的任务无法在重连后同步到服务端
- 无法实现断点续传式的状态恢复

**证据**:
```python
# TaskDatabase.py 中的表结构
# - unified_commands: 保存命令状态
# - tasks: 保存任务状态
# - task_history: 保存执行历史
# 但没有：
# - hardware_state: 硬件状态表
# - system_state: 系统运行状态表
```

---

#### 问题6: 断线后任务执行缺乏状态同步
**现状描述**:
- 用户选择"断线继续执行任务"
- 但没有机制在重连后同步断线期间的任务进度和结果
- 服务端无法得知机器人在断线期间做了什么

**影响**:
- 服务端任务状态与机器人实际状态不一致
- 无法追溯断线期间的操作历史
- 影响数据完整性和可追溯性

---

#### 问题7: 异常处理和错误恢复不足
**现状分析**:
- 大量使用通用 `except Exception` 捕获所有异常
- 没有区分可恢复错误和致命错误
- 错误发生后缺少自动恢复机制

**影响**:
- 小错误可能导致整个系统停止
- 难以定位问题根源
- 无法实现故障自愈

**证据**:
```bash
# Grep结果显示15个文件中有151处Exception使用
# 大部分是通用异常处理，没有细分错误类型
```

---

#### 问题8: 缺少系统健康监控
**现状描述**:
- 没有统一的健康检查机制
- 无法主动发现子系统异常
- 依赖被动的错误上报

**影响**:
- 硬件故障可能长时间未被发现
- 无法提前预警和主动维护
- 影响系统可靠性

---

#### 问题9: 配置管理不规范
**现状描述**:
- 配置从 `conf/config.json` 读取
- 没有配置验证机制
- 不支持配置热重载
- 配置错误在运行时才暴露

**影响**:
- 配置错误导致启动失败
- 修改配置需要重启整个系统
- 缺少配置版本管理

---

### 1.2 用户需求明确

根据用户问卷回答：

1. **硬件控制**: 分组控制 - AGV、机械臂、外部轴可独立启动/关闭/使能
2. **断线处理**: 继续执行当前任务，重连后同步状态
3. **安全机制**: 手动控制无需额外校验（用户已确认）
4. **状态恢复**: 程序重启后清空未完成任务

## 三、详细改进内容

### 3.1 gRPC持续连接和自动重连机制 (P0)

#### 改进点1: 心跳和健康检查
**目标**: 及时发现连接断开，触发重连

**实现内容**:
1. 在 `BaseStreamManager` 中增加心跳线程
   - 每30秒发送一次心跳消息
   - 检测心跳响应超时（60秒）
   - 超时标记流为不健康状态

2. 在 `RobotControlSystem` 中增加连接监控线程
   - 每10秒检查流健康状态
   - 检测到不健康时触发重连

**新增属性**:
```python
# BaseStreamManager
self.last_heartbeat_time = None
self.heartbeat_timeout = 60.0
self.heartbeat_thread = None

# RobotControlSystem
self.connection_monitor_thread = None
self._connection_monitor_running = False
```

---

#### 改进点2: 断线重连机制
**目标**: 连接断开后自动恢复

**实现策略**: 指数退避重连
- 首次重连: 立即
- 后续重连: 2秒、4秒、8秒、16秒、30秒（最大）
- 最大重试次数: 无限（持续重连）

**实现内容**:
1. 新增 `_reconnect()` 方法
   - 关闭旧连接和流
   - 重新建立channel和stub
   - 重新启动双向流
   - 重新注册回调函数

2. 重连时的数据处理
   - 重连期间的消息缓存在本地队列
   - 重连成功后批量发送缓存消息
   - 发送断线期间的状态同步消息

**新增方法**:
```python
# RobotControlSystem
def _reconnect(self) -> bool
def _monitor_connection(self)  # 监控线程
def _sync_offline_state(self)  # 同步断线期间状态
```

---

#### 改进点3: 消息缓存机制
**目标**: 断线期间不丢失消息

**实现内容**:
1. 在 `StreamManager` 中增加离线消息缓存
   - 最大缓存1000条消息
   - 使用文件持久化（防止程序崩溃）
   - FIFO策略，缓存满时丢弃最旧消息

2. 重连后批量发送
   - 限速发送，避免流量激增
   - 发送失败的消息重新入队

**新增属性**:
```python
# StreamManager
self.offline_message_cache = []
self.max_cache_size = 1000
self.cache_file_path = "logs/offline_cache.json"
```

#### 改进点14: 实现错误恢复策略

**错误处理装饰器**:
```python
# utils/error_handler.py
from functools import wraps
import time

def with_retry(max_retries=3, delay=1.0, backoff=2.0,
               recoverable_exceptions=(RobotSystemException,)):
    """重试装饰器"""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            retries = 0
            current_delay = delay

            while retries <= max_retries:
                try:
                    return func(*args, **kwargs)
                except recoverable_exceptions as e:
                    if not e.recoverable or retries >= max_retries:
                        raise
                    retries += 1
                    logger.warning(f"{func.__name__}失败，{current_delay}秒后重试 ({retries}/{max_retries})")
                    time.sleep(current_delay)
                    current_delay *= backoff

        return wrapper
    return decorator

def with_fallback(fallback_func):
    """失败回退装饰器"""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            try:
                return func(*args, **kwargs)
            except Exception as e:
                logger.error(f"{func.__name__}失败，执行回退方案: {e}")
                return fallback_func(*args, **kwargs)
        return wrapper
    return decorator
```

```python
                self._apply_config_changes(new_config)
        except Exception as e:
            self.logger.error(f"配置重载失败: {e}")

        time.sleep(60)  # 每分钟检查一次

def _apply_config_changes(self, new_config: Dict):
    """应用配置变更（部分参数可热更新）"""
    # 可热更新的配置
    if new_config['log_config'] != self.config['log_config']:
        self._update_log_config(new_config['log_config'])

    # 不可热更新的配置（需要重启）
    if new_config['grpc_config'] != self.config['grpc_config']:
        self.logger.warning("gRPC配置变更，需要重启系统生效")
```
