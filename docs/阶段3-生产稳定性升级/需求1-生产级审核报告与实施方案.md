### 🔴 严重问题1：消息序列化方案与现有架构冲突

#### 问题描述

**外包方案**：
```python
# 外包建议使用 google.protobuf.json_format.MessageToJson()
payload_json = MessageToJson(message_obj)
```

**现实情况**：
根据 `CLAUDE.md` 和 `utils/dataConverter.py`，你的系统**已经有完整的序列化体系**：

```python
# 现有转换路径（clientUpload流）
MessageEnvelope (Python dataclass)
    ↓ convert_message_envelope_to_robot_upload_request()
RobotUploadRequest (protobuf)
    ↓ 发送

# 现有转换路径（serverCommand流）
直接构造 ClientStreamMessage (protobuf)
    ↓ 发送
```

如果引入新的JSON序列化，会：
- 破坏现有的转换逻辑
- 与 `dataConverter.py` 的设计冲突
- 增加不必要的复杂度

#### ✅ 修正方案

**不使用JSON序列化**，而是利用 protobuf 自带的序列化能力：

```python

from gRPC import RobotService_pb2
from utils.logger_config import get_logger

logger = get_logger(__name__)

class OfflineMessageHandler:
    """离线消息序列化/反序列化处理器"""
    
    # 消息类型映射表
    MESSAGE_TYPE_MAP = {
        'RobotUploadRequest': RobotService_pb2.RobotUploadRequest,
        'ClientStreamMessage': RobotService_pb2.ClientStreamMessage,
    }
    
    @staticmethod
    def serialize_message(message_obj):
        """
        序列化 protobuf 消息为二进制
        
        Args:
            message_obj: protobuf消息对象
            
        Returns:
            tuple: (msg_type_name: str, message_bytes: bytes)
        """
        msg_type_name = type(message_obj).__name__
        message_bytes = message_obj.SerializeToString()
        return msg_type_name, message_bytes
    
    @staticmethod
    def deserialize_message(msg_type_name: str, message_bytes: bytes):
        """
        反序列化二进制数据为 protobuf 消息
        
        Args:
            msg_type_name: 消息类型名称
            message_bytes: 二进制数据
            
        Returns:
            protobuf消息对象
        """
        if msg_type_name not in OfflineMessageHandler.MESSAGE_TYPE_MAP:
            raise ValueError(f"未知的消息类型: {msg_type_name}")
        
        message_class = OfflineMessageHandler.MESSAGE_TYPE_MAP[msg_type_name]
        message_obj = message_class()
        message_obj.ParseFromString(message_bytes)
        
        return message_obj
```

### 🔴 严重问题2：StreamManager修改方式破坏现有架构

#### 问题描述

**外包方案**建议在 `BaseStreamManager.send_message()` 中判断流状态，直接调用数据库：

```python
# 外包建议（❌ 错误）
def send_message(self, message):
    if not self.is_stream_active and self.on_message_failed:
        self.on_message_failed(message, msg_type_name)  # 直接回调
        return True
```

**问题**：
1. **违反单一职责原则**：StreamManager应该只负责流管理，不应涉及持久化
2. **破坏现有架构**：根据 `CLAUDE.md`，"RobotControlSystem仅负责gRPC通信"，缓存逻辑应在更高层
3. **可测试性差**：StreamManager与数据库耦合，难以单独测试

#### ✅ 修正方案

**保持StreamManager职责纯粹**，只负责流管理和消息队列：

```python
# gRPC/StreamManager.py 修改

class BaseStreamManager:
    """基础流管理器（修正版）"""
    
    def __init__(self, stream, stub, robot_id, logger, shutdown_event):
        # ... 现有初始化 ...
        
        # 新增：断线回调（通知上层）
        self.on_stream_broken: Optional[Callable[[str], None]] = None
        
        # 新增：消息发送失败回调（通知上层缓存）
        self.on_message_send_failed: Optional[Callable[[Any], bool]] = None
        
        # 新增：活动时间戳（用于心跳超时检测）
        self.last_activity = time.time()
        
        self.logger.info(f"{self.__class__.__name__} 初始化完成")
    
    def send_message(self, message) -> bool:
        """
        发送消息（修正版）
        
        Args:
            message: protobuf消息对象
            
        Returns:
            bool: 是否成功处理（包括缓存）
        """
        # 1. 如果流活跃，正常发送
        if self.is_stream_active:
            try:
                self._message_queue.put(message, timeout=1)
                self.last_activity = time.time()  # 更新活动时间
                return True
            except queue.Full:
                self.logger.warning(f"{self.__class__.__name__}: 消息队列已满")
                # 队列满也尝试缓存
                if self.on_message_send_failed:
                    return self.on_message_send_failed(message)
                return False
        
        # 2. 流未激活，调用失败回调（由上层决定如何处理，通常是缓存）
        if self.on_message_send_failed:
            self.logger.debug(f"{self.__class__.__name__}: 流未激活，消息交由上层缓存")
            return self.on_message_send_failed(message)
        
        # 3. 没有失败回调，直接丢弃（向后兼容）
        self.logger.warning(f"{self.__class__.__name__}: 流未激活且无缓存回调，消息丢失")
        return False
    
    def _handle_responses(self):
        """响应处理循环（修正版）"""
        try:
            self.logger.info(f"{self.__class__.__name__} 开始处理响应")
            
            for response in self.stream:
                self.last_activity = time.time()  # 更新活动时间
                
                # 处理响应（子类实现）
                self._process_response(response)
                
        except grpc.RpcError as e:
            # 记录错误
            self.logger.error(f"{self.__class__.__name__} gRPC错误: {e}")
            self.error_count += 1
            
        finally:
            self.is_stream_active = False
            
            # 如果不是正常关闭（shutdown_event未设置），触发断线回调
            if not self.shutdown_event.is_set() and self.on_stream_broken:
                self.logger.warning(f"{self.__class__.__name__} 流异常断开，触发回调")
                self.on_stream_broken(self.__class__.__name__)
            
            self.logger.info(f"{self.__class__.__name__} 响应处理线程结束")
```

### 🔴 严重问题3：心跳超时检测位置错误

#### 问题描述

**外包方案**建议在重连循环中检测心跳超时：

```python
# 外包建议（❌ 错误）
def _reconnect_loop(self):
    while not self._stop_reconnect:
        # 检查心跳超时
        if time_since_activity > heartbeat_timeout:
            # 触发重连
```

**问题**：
1. **逻辑矛盾**：重连循环只在断线后才运行，而心跳检测需要在**连接正常时**运行
2. **检测延迟**：重连循环有长时间sleep，心跳超时检测会严重滞后
3. **与需求冲突**：需求要求"30秒内开始重连"，但这个设计无法保证

#### ✅ 修正方案

**独立的心跳监控线程**，在连接正常时持续监控：

```python
# RobotControlSystem.py

class RobotControlSystem:
    """主控制系统（修正版）"""
    
    def __init__(self, config_path: str = "conf/config.json"):
        # ... 现有初始化 ...
        
        # 连接状态管理
        from enum import Enum
        
        class ConnectionState(Enum):
            DISCONNECTED = "disconnected"
            CONNECTING = "connecting"
            CONNECTED = "connected"
            RECONNECTING = "reconnecting"
        
        self.ConnectionState = ConnectionState  # 保存枚举类
        self._connection_state = ConnectionState.DISCONNECTED
        self._connection_lock = threading.Lock()
        
        # 重连控制
        self._reconnect_trigger = threading.Event()  # 重连触发器
        self._shutdown_event = threading.Event()  # 全局关闭信号
        
        # 重连配置
        reconnect_cfg = self.grpc_config.get("reconnect", {})
        self.reconnect_base_delay = reconnect_cfg.get("base_delay", 2)
        self.reconnect_max_delay = reconnect_cfg.get("max_delay", 30)
        self.heartbeat_timeout = reconnect_cfg.get("heartbeat_timeout", 60)
        
        self.logger.info("RobotControlSystem 初始化完成")
    
    def _get_connection_state(self):
        """线程安全地获取连接状态"""
        with self._connection_lock:
            return self._connection_state
    
    def _set_connection_state(self, new_state):
        """线程安全地设置连接状态"""
        with self._connection_lock:
            old_state = self._connection_state
            if old_state == new_state:
                return  # 状态未变化
            
            self._connection_state = new_state
            self.logger.info(f"连接状态变更: {old_state.value} → {new_state.value}")
            
            # 转换到DISCONNECTED或RECONNECTING时，触发重连
            if new_state in [self.ConnectionState.DISCONNECTED, self.ConnectionState.RECONNECTING]:
                self._reconnect_trigger.set()
    
    def _start_heartbeat_monitor(self):
        """启动心跳监控线程（独立运行）"""
        self._heartbeat_thread = threading.Thread(
            target=self._heartbeat_monitor_loop,
            daemon=True,
            name="HeartbeatMonitor"
        )
        self._heartbeat_thread.start()
        self.logger.info("心跳监控线程已启动")
    
    def _heartbeat_monitor_loop(self):
        """
        心跳超时监控循环
        每5秒检查一次，如果超过heartbeat_timeout无活动，判定断线
        """
        check_interval = 5  # 每5秒检查一次
        
        while not self._shutdown_event.is_set():
            time.sleep(check_interval)
            
            # 只在CONNECTED状态检测超时
            if self._get_connection_state() != self.ConnectionState.CONNECTED:
                continue
            
            # 检查两个流的活动时间
            now = time.time()
            
            upload_inactive = now - getattr(self.client_upload_manager, 'last_activity', now)
            command_inactive = now - getattr(self.server_command_manager, 'last_activity', now)
            
            # 任一流超时都判定断线
            if upload_inactive > self.heartbeat_timeout:
                self.logger.warning(
                    f"clientUpload流心跳超时 ({upload_inactive:.1f}秒无活动，阈值{self.heartbeat_timeout}秒)"
                )
                self._set_connection_state(self.ConnectionState.DISCONNECTED)
                
            elif command_inactive > self.heartbeat_timeout:
                self.logger.warning(
                    f"serverCommand流心跳超时 ({command_inactive:.1f}秒无活动，阈值{self.heartbeat_timeout}秒)"
                )
                self._set_connection_state(self.ConnectionState.DISCONNECTED)
```

### 🔴 严重问题4：重连流程未考虑现有架构

#### 问题描述

**外包方案**建议直接调用 `_init_grpc_client()` 重连，但这会：
1. 与现有的 `start()` 方法冲突
2. 无法正确清理旧资源
3. 未考虑 TaskManager 的状态

根据 `CLAUDE.md`，你的系统有严格的启动流程：
```python
RobotControlSystem.start()
    ├── _init_grpc_client()
    ├── task_manager初始化
    └── 定时上报循环
```

#### ✅ 修正方案

**设计符合现有架构的重连流程**：

```python
# RobotControlSystem.py

def start(self):
    """启动系统（修正版，支持重连）"""
    try:
        self.logger.info("=" * 60)
        self.logger.info("机器人控制系统启动中...")
        self.logger.info("=" * 60)
        
        # 1. 首次连接gRPC
        if not self._init_grpc_client():

            self._set_connection_state(self.ConnectionState.CONNECTED)

        self._start_reporting()
        
        self.logger.info("=" * 60)
        self.logger.info("机器人控制系统启动完成")
        self.logger.info("=" * 60)
        
        # 主线程保持运行
        try:
            while not self._shutdown_event.is_set():
                time.sleep(1)
        except KeyboardInterrupt:
            self.logger.info("收到中断信号，准备关闭...")
            self.shutdown()
            
    except Exception as e:

def _init_grpc_client(self) -> bool:
    """
    初始化gRPC客户端（修正版，返回是否成功）
    
    Returns:
        bool: 是否成功建立连接
    """
    try:
        server_host = self.grpc_config.get("server_host", "localhost")
        server_port = self.grpc_config.get("server_port", 50051)
        connection_timeout = self.grpc_config.get("connection_timeout", 10)
        
        target = f"{server_host}:{server_port}"
        self.logger.info(f"正在连接gRPC服务器: {target}")
        
        # 创建channel（设置超时）
        self.channel = grpc.insecure_channel(
            target,
            options=[
                ('grpc.keepalive_time_ms', 30000),  # 30秒发送keepalive
                ('grpc.keepalive_timeout_ms', 10000),  # 10秒超时
                ('grpc.keepalive_permit_without_calls', 1),
                ('grpc.http2.max_pings_without_data', 0),
            ]
        )
        
        # 验证连接（使用grpc的channel_ready_future，有超时）
        try:
            grpc.channel_ready_future(self.channel).result(timeout=connection_timeout)
        except grpc.FutureTimeoutError:
            self.logger.error(f"连接超时（{connection_timeout}秒）")
            if self.channel:
                self.channel.close()
            self.channel = None
            return False
        
        # 创建stub
        self.stub = RobotService_pb2_grpc.RobotServiceStub(self.channel)
        
        # 初始化流管理器
        self.client_upload_manager = ClientUploadStreamManager(
            stub=self.stub,
            robot_id=self.robot_id,
            logger=self.logger,
            shutdown_event=self._shutdown_event
        )
        
        self.server_command_manager = ServerCommandStreamManager(
            stub=self.stub,
            robot_id=self.robot_id,
            logger=self.logger,
            shutdown_event=self._shutdown_event,
            command_callback=self._handle_server_command
        )
        
        # 注册回调
        self._register_stream_callbacks()
        
        # 启动流
        self.client_upload_manager.start_stream()
        self.server_command_manager.start_with_heartbeat(interval=30)  # 30秒心跳
        
        self.logger.info("gRPC客户端初始化成功")
        return True
        
    except Exception as e:
        self.logger.error(f"gRPC客户端初始化失败: {e}", exc_info=True)
        return False

def _register_stream_callbacks(self):
    """注册流管理器的回调"""
    # 注册断线回调
    if self.client_upload_manager:
        self.client_upload_manager.on_stream_broken = self._on_stream_broken
        self.client_upload_manager.on_message_send_failed = self._on_message_send_failed
    
    if self.server_command_manager:
        self.server_command_manager.on_stream_broken = self._on_stream_broken
        self.server_command_manager.on_message_send_failed = self._on_message_send_failed

def _on_stream_broken(self, stream_name: str):
    """
    流断开回调（由StreamManager触发）
    
    Args:
        stream_name: 断开的流名称
    """
    self.logger.warning(f"检测到流断开: {stream_name}")
    
    # 只有在CONNECTED状态才转换到DISCONNECTED
    current_state = self._get_connection_state()
    if current_state == self.ConnectionState.CONNECTED:
        self._set_connection_state(self.ConnectionState.DISCONNECTED)
    else:
        self.logger.debug(f"流断开但当前已是{current_state.value}状态，无需重复处理")

def _on_message_send_failed(self, message) -> bool:
    """
    消息发送失败回调（流未激活时触发）
    将消息缓存到离线数据库
    
    Args:
        message: protobuf消息对象
        
    Returns:
        bool: 是否成功缓存
    """
    try:
        from utils.offline_message_handler import OfflineMessageHandler
        
        # 序列化消息
        msg_type_name, message_bytes = OfflineMessageHandler.serialize_message(message)
        
        # 确定stream_type
        from gRPC import RobotService_pb2
        if isinstance(message, RobotService_pb2.RobotUploadRequest):
            stream_type = 'client_upload'
        elif isinstance(message, RobotService_pb2.ClientStreamMessage):
            stream_type = 'server_command'
        else:
            self.logger.warning(f"未知的消息类型: {msg_type_name}")
            return False
        
        # 保存到数据库
        msg_id = self.task_database.save_offline_message(
            stream_type=stream_type,
            message_bytes=message_bytes,
            msg_type_name=msg_type_name,
            robot_id=str(self.robot_id)
        )
        
        return True
        
    except Exception as e:
        self.logger.error(f"缓存离线消息失败: {e}", exc_info=True)
        return False
```

### 🔴 严重问题5：重连流程缺少完整的资源管理

#### 问题描述

外包方案的 `_try_reconnect()` 过于简化，未考虑：
1. 旧连接的优雅关闭
2. 线程的正确停止
3. 失败时的回滚机制

#### ✅ 修正方案

**完整的重连流程，包含资源清理和失败回滚**：

```python
# RobotControlSystem.py

def _start_reconnect_manager(self):
    """启动重连管理器线程"""
    self._reconnect_thread = threading.Thread(
        target=self._reconnect_manager_loop,
        daemon=True,
        name="ReconnectManager"
    )
    self._reconnect_thread.start()
    self.logger.info("重连管理器已启动")

def _reconnect_manager_loop(self):
    """
    重连管理器主循环
    等待断线事件，然后进行指数退避重连
    """
    attempt = 0
    
    while not self._shutdown_event.is_set():
        # 等待重连触发（阻塞直到有断线事件或超时）
        triggered = self._reconnect_trigger.wait(timeout=30)
        
        if not triggered:
            continue  # 超时，继续等待
        
        # 清除触发标志
        self._reconnect_trigger.clear()
        
        # 设置为重连中状态
        self._set_connection_state(self.ConnectionState.RECONNECTING)
        
        # 指数退避重连
        while self._get_connection_state() == self.ConnectionState.RECONNECTING:
            # 计算延迟
            delay = min(self.reconnect_base_delay * (2 ** attempt), self.reconnect_max_delay)
            
            self.logger.info(f"准备重连（第{attempt + 1}次尝试，延迟{delay}秒）...")
            
            # 可中断的sleep
            if self._shutdown_event.wait(timeout=delay):
                self.logger.info("收到关闭信号，停止重连")
                return
            
            # 尝试重连
            success = self._try_reconnect()
            
            if success:
                self.logger.info("✅ 重连成功！")
                self._set_connection_state(self.ConnectionState.CONNECTED)
                attempt = 0  # 重置重试次数
                
                # 重发离线消息
                self._flush_offline_messages()
                break
            else:
                attempt += 1
                self.logger.warning(f"❌ 重连失败，将在{delay}秒后重试")

def _try_reconnect(self) -> bool:
    """
    尝试重新连接（完整版）
    
    Returns:
        bool: 是否成功
    """
    try:
        self.logger.info("开始重连流程...")
        
        # 步骤1: 清理旧连接
        self._cleanup_old_connection()
        
        # 步骤2: 重新建立连接
        if not self._init_grpc_client():
            self.logger.warning("gRPC连接建立失败")
            return False
        
        # 步骤3: 验证连接
        if not self._verify_grpc_connection():
            self.logger.warning("gRPC连接验证失败")
            return False
        
        self.logger.info("重连流程完成")
        return True
        
    except Exception as e:
        self.logger.error(f"重连过程异常: {e}", exc_info=True)
        return False

def _cleanup_old_connection(self):
    """清理旧的gRPC连接（非阻塞）"""
    try:
        self.logger.info("清理旧连接...")
        
        # 1. 停止流管理器（设置shutdown标志，不等待线程）
        if hasattr(self, 'client_upload_manager') and self.client_upload_manager:
            self.client_upload_manager.shutdown_event.set()
            self.client_upload_manager.is_stream_active = False
        
        if hasattr(self, 'server_command_manager') and self.server_command_manager:
            self.server_command_manager.shutdown_event.set()
            self.server_command_manager.is_stream_active = False
        
        # 2. 关闭channel（有超时保护）
        if hasattr(self, 'channel') and self.channel:
            try:
                # 立即关闭，不等待
                self.channel.close()
            except Exception as e:
                self.logger.warning(f"关闭旧channel失败（忽略）: {e}")
        
        # 3. 清空引用
        self.channel = None
        self.stub = None
        
        # 4. 重建shutdown_event（重连时需要新的事件对象）
        # 注意：不能重建_shutdown_event，因为它是全局关闭信号
        # StreamManager会用新的shutdown_event
        
        self.logger.info("旧连接已清理")
        
    except Exception as e:
        self.logger.warning(f"清理旧连接时出错（继续重连）: {e}")

def _verify_grpc_connection(self) -> bool:
    """
    验证gRPC连接是否真正可用
    
    Returns:
        bool: 连接是否可用
    """
    try:
        # 检查流管理器是否启动成功
        if not self.client_upload_manager or not self.client_upload_manager.is_stream_active:
            self.logger.warning("clientUpload流未激活")
            return False
        
        if not self.server_command_manager or not self.server_command_manager.is_stream_active:
            self.logger.warning("serverCommand流未激活")
            return False
        
        self.logger.info("gRPC连接验证通过")
        return True
        
    except Exception as e:
        self.logger.error(f"连接验证失败: {e}")
        return False

def _flush_offline_messages(self):
    """
    重发离线消息（增强版）
    
    特性:
    - 分批读取和发送
    - 失败消息保留，下次重连继续
    - 支持中断（再次断线）
    """
    from utils.offline_message_handler import OfflineMessageHandler
    
    batch_size = 10  # 每批10条
    batch_interval = 0.1  # 批间间隔100ms
    
    for stream_type in ['client_upload', 'server_command']:
        self.logger.info(f"开始重发 {stream_type} 离线消息...")
        
        total_sent = 0
        total_failed = 0
        
        while True:
            # 检查是否再次断线
            if self._get_connection_state() != self.ConnectionState.CONNECTED:
                self.logger.warning("重发过程中检测到断线，暂停重发")
                break
            
            # 分批读取
            messages = self.task_database.get_offline_messages_for_resend(
                stream_type=stream_type,
                limit=batch_size
            )
            
            if not messages:
                break  # 没有更多消息
            
            # 逐条重发
            for msg_data in messages:
                try:
                    # 反序列化
                    message = OfflineMessageHandler.deserialize_message(
                        msg_data['msg_type'],
                        msg_data['payload_blob']
                    )
                    
                    # 选择管理器
                    if stream_type == 'client_upload':
                        manager = self.client_upload_manager
                    else:
                        manager = self.server_command_manager
                    
                    # 发送（直接入队，不走缓存逻辑）
                    if manager and manager.is_stream_active:
                        manager._message_queue.put(message, timeout=1)
                        
                        # 删除已发送的消息
                        self.task_database.delete_offline_message(msg_data['msg_id'])
                        total_sent += 1
                    else:
                        self.logger.warning(f"流{stream_type}未激活，停止重发")
                        break
                        
                except Exception as e:
                    self.logger.error(f"重发消息失败: {e}")
                    total_failed += 1
                    # 失败的消息保留在数据库
            
            # 批间延迟
            time.sleep(batch_interval)
        
        self.logger.info(
            f"{stream_type} 离线消息重发完成: "
            f"成功{total_sent}条, 失败{total_failed}条"
        )
```

```python
def cleanup_old_offline_messages(self, days: int = 7):

    deleted_count = cursor.rowcount

def get_offline_message_stats(self):
    """获取离线消息统计"""
    query = """
        SELECT stream_type, COUNT(*) as count, 
               MIN(msg_time) as oldest, MAX(msg_time) as newest
        FROM offline_messages
        GROUP BY stream_type
    """
    cursor = self.execute(query)
    
    stats = {}
    for row in cursor.fetchall():
        stats[row[0]] = {
            'count': row[1],
            'oldest': row[2],
            'newest': row[3]
        }
    
    return stats
```

```python
# RobotControlSystem.py

def _start_maintenance_tasks(self):

    def maintenance_loop():
        while not self._shutdown_event.is_set():
            try:
```

```python
# RobotControlSystem.py

class ReconnectStatistics:
    """重连统计（简化版）"""
    
    def __init__(self):
        self.total_attempts = 0  # 总尝试次数
        self.successful_reconnects = 0  # 成功次数
        self.failed_attempts = 0  # 失败次数
        self.last_reconnect_time = 0  # 最后重连时间
        self.current_connected_since = 0  # 当前连接建立时间
    
    def record_attempt(self, success: bool):
        """记录一次重连尝试"""
        self.total_attempts += 1
        if success:
            self.successful_reconnects += 1
            self.last_reconnect_time = time.time()
            self.current_connected_since = time.time()
        else:
            self.failed_attempts += 1
    
    def get_stats(self) -> dict:
        """获取统计数据"""
        uptime = time.time() - self.current_connected_since if self.current_connected_since > 0 else 0
        
        return {
            'total_attempts': self.total_attempts,
            'successful': self.successful_reconnects,
            'failed': self.failed_attempts,
            'success_rate': self.successful_reconnects / max(self.total_attempts, 1),
            'last_reconnect': self.last_reconnect_time,
            'current_uptime': uptime
        }

# 在RobotControlSystem.__init__中添加
self.reconnect_stats = ReconnectStatistics()

# 在_try_reconnect中记录
success = self._try_reconnect()
self.reconnect_stats.record_attempt(success)
```

## 六、风险评估和缓解措施

### 高风险项

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| 重连失败导致系统无法恢复 | 🔴 严重 | 中 | 添加人工重启接口；记录详细日志便于排查 |
| 离线消息过多导致内存溢出 | 🔴 严重 | 低 | 分批读取；设置单批大小限制；定期清理 |
| 线程竞争导致死锁 | 🔴 严重 | 低 | 使用明确的锁顺序；避免嵌套锁；超时保护 |
| protobuf序列化兼容性问题 | 🟡 中等 | 低 | 使用成熟的SerializeToString；版本控制 |

### 中风险项

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| 重连延迟过长影响业务 | 🟡 中等 | 中 | 可配置的重连参数；支持运行时调整 |
| 数据库性能瓶颈 | 🟡 中等 | 低 | 使用索引；批量操作；定期清理 |
| 心跳检测误报 | 🟡 中等 | 低 | 合理设置超时阈值（60秒）；双重检测机制 |
